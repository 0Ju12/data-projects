# wildfire-watch — 화재기상지수와 위성 화재 탐지를 매일 맞춰 보기

날씨로 계산한 **화재기상지수(FFWI)** 와 위성이 실제로 탐지한 **열원(NASA FIRMS)** 을 매일 모아,
"지수가 높았던 곳에서 정말 불이 더 났는가"를 계속 기록합니다.

**직접 보기 → [산불 위험 지도](https://0ju12.github.io/data-projects/fire/)** (GitHub Actions 로 매일 갱신)

학부 연구에서는 시공간 딥러닝(U-LSTM)으로 산불 확산을 예측했습니다. 그 모델의 학습 자료는 공개할 수 없어,
여기서는 공개 자료만으로 **수집 → 정제 → 기준선 지수 → 실제 탐지와 비교**까지 매일 도는 구조를 먼저 만들었습니다.
지수는 기상만 쓰는 기준선이고, 딥러닝 모델이 아닙니다.

## 흐름

```
FIRMS VIIRS 375 m (NOAA-20·21·SNPP, 최근 7일 CSV) ─► 한국 범위·신뢰도 필터 ─► 중복 없이 합치기 ─┐
                                                                                          ├─► 상시 열원 가려내기 ─► 육지 칸 × 날짜 양성
Open-Meteo 일 기상 (0.25° 육지 칸 153개, 지난 10일 + 예보 3일) ─► FFWI ───────────────────────┘        │
                                                                                                    ▼
                                                              AUC · 상위 20% 적중률 ─► docs/data.json ─► 지도
```

## 처음 돌려 보고 알게 된 것 (2026-11-11 기준, `data/summary.json`)

| 항목 | 값 |
|---|---|
| 모은 탐지 (11-03 ~ 11-11) | 394건 |
| 상시 열원으로 걸러낸 것 | 356건 (**90%**) — 광양·포항·당진 제철소, 동해·삼척 시멘트 공장, 울산 |
| 육지 칸 안의 화재 의심 | 20건 → 칸·날로 10건 |
| 평가 (11-04 ~ 11-10, 1,071 칸·날) | AUC **0.57**, 지수 상위 20% 칸 적중 **0 / 10** |

- **위성 탐지를 그대로 '화재'로 쓰면 안 됩니다.** 한국에서는 열 탐지 열 건 중 아홉 건이 같은 자리에서 반복되는 산업 시설이었습니다.
  같은 자리(약 1 km)에서 서로 다른 날 3일 이상 잡히면 상시 열원으로 보고 빼는 규칙을 넣었습니다(`firewatch/sources.py`).
- **지수가 맞는지는 아직 말할 수 없습니다.** 양성이 10건뿐이라 AUC 0.57 은 무작위(0.5)와 구분되지 않습니다.
  11월은 산불이 적은 철이기도 합니다. 자료가 매일 쌓이므로 봄철(2~5월)을 지나야 판단할 수 있습니다.
- 남은 '화재 의심'에도 하루 이틀만 잡힌 공장·소각이 섞여 있을 수 있습니다. 반대로 여러 날 이어진 큰 산불은 상시 열원으로 잘못 걸러질 수 있습니다.

## 설계 판단

- **여러 번 돌려도 결과가 같게**: 탐지는 (위성, 날짜, 시각, 위·경도)로 구분해 한 번만 저장. 기상은 (칸, 날짜)마다 한 줄이고 새 값이 예보를 덮어쓰되, 지난 날 값을 예보로 되돌리지는 않음.
- **날짜 맞추기**: FIRMS 시각은 UTC → 한국 날짜로 바꿔 기상과 맞춤. 구간 양 끝 날은 위성 자료가 하루를 다 덮지 못해 평가에서 뺌.
- **한 곳이 실패해도 끝까지**: 위성 파일 하나나 기상 API 가 실패해도 받은 것은 저장하고 상태를 `summary.json` 에 남김.
- **지수의 한계를 그대로 적기**: FFWI 는 기온·습도·풍속만 씀. 강수 이력·연료 상태는 없음. 하루 중 최고기온·최저습도·최대풍속을 함께 넣은 '가장 나쁜 조건' 근사.

## 실행

```bash
python -m firewatch.cli run      # 받기 → 합치기 → 평가 → docs/data.json
python -m firewatch.cli build    # 저장된 자료로 다시 계산만 (네트워크 없음)
python -m pytest -q              # 8 passed
```

표준 라이브러리만 씁니다(테스트는 pytest).
